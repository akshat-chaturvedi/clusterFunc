#Documentation for Globular Cluster Project Code
The overall data reduction and analysis pipeline codebase consists of 9 python scripts.
These are:
baumgardtComparer.py - contains code for comparison of our candidate stars with the V&B21 data
clusterProps.py - contains a dictionary with information for each cluster obtained from the Harris 2010 GC catalogue
GaiaQuerier.py - contains the code to query the Gaia DR3 database to create a Gaia matches file for a cluster (not needed for the most part as I have done this for almost all the clusters already)
GCAnalyzer.py - contains the main code pipeline tying in all the other scripts, creates most of the resultant data files
GCAnalyzerHelperFunctions.py - helper functions for GCAnalyzer.py
GCDBSCAN.py - contains the code for the DBSCAN clustering algorithm that is run on the Gaia proper motions of the matches for our stars
globClust.py - just a runner script for the pipeline, i.e. runs the actual code itself
GMagCalculator.py - calculates the G magnitudes for each star in our datasets (post initial data cleanup), creates the files used to find Gaia matches
secondaryAnalysisHelperFunctions.py - contains the code for analysis of the resultant data files, mainly bookkeeping stuff, creates the overall CMDs for all the candidate stars found so far

A data analysis run looks like this:
1. Navigate to the directory containing the code and data files.

2. In the terminal (or wherever you like to run python scripts) run the globClust.py file

3. A prompt will show up asking you to enter the cluster name (you can look through the clusterProps.py files to see how the names are characterized). Enter the required cluster name.

4. Another prompt will then ask for the extension. This is mainly to keep track of files as you work with them. The default option is the current month. You can also enter any extension you want.

5. The code will look to see if the relevant data files (.phot file, the G magnitudes file and the Gaia matches file) exist. If they do, it will continue running. If the .phot file doesn't  exist, the code will exit. If any of the other files don't exist, it will ask you if you want to create them^. The code then performs an initial cleanup by removing any objects that have a B or V magnitude higher than 60 (as the bad matches are given values of 99.9) as well as a chi^2 value of greater than 3 and an absolute sharp value greater than 0.5. It then dereddens the remaining stars using Gautam's dereddening algorithm.

6. Assuming the Gaia matches file exists, the code will perform a check to get rid of any duplicates/multiple matches for single stars it finds in the Gaia matches. The resultant stars are then used for the DBSCAN algorithm

7. If all the necessary files are present, the code will continue onto the DBSCAN portion. Here, it will check if the ideal DBSCAN parameters file exists, and if it doesn't, it will go through the parameter optimization using a silhouette score maximization algorithm. It will then perform the DBSCAN algorithm to find the first set of candidate cluster members.

8. The code will then go through another set of checks to certify cluster membership. These include testing whether the star lies within the tidal radius of the cluster, checking to see if the parallax of the star +/- 5*sigma matches the parallax of the cluster. Only if a star fits all these criteria is it found to be a cluster member, and is recorded in the cluster members data file. All the stars found to be non-members are recorded in the non-members data file along with the reason they were kicked out.

9. Using these cluster members, V vs B-V and U vs B-V CMDs are plotted. There are two types of main CMDs that are plotted: one set made using the dereddened magnitudes and one made using the raw values. The dereddned CMDs contain a horizontal branch (HB, shown in red) modeled by a sixth-degree polynomial.  The parameters for this polynomial are stored in the HBParams directory, and if they don't exist for a given cluster, a prompt will ask to use the default values (the values for M79). To change the parameters for the HB, you need to change them in these files. These CMDs also contain a vertical line at (B-V)0 = 0. The code then performs a check to see which stars lie above (are brighter than) the HB and are blueward of (less than) (B-V)0 = 0. These stars are circled in green in both sets of CMDs and are recorded in the cadStar files.

10. The code then checks these candidate stars against the Vasiliev and Baumgardt 2021 (VB21) data to see if they agree on its cluster membership. This is done using a position and magnitude check on our candidate stars against theirs, and if there is at least one star in common within a radius of 3" and a Gaia G magnitude difference of less than 0.5, then we say that it is a VB21 match as well. These are recorded in the candStarWithProbs files.

^The Gaia matches file is created using the astroquery.gaia module. It requires a Gaia archive account, the credentials for which it will ask you if you query the database to find the matches. The Gaia ADQL query looks for Gaia objects within an arc second of our stars and having a G magnitude within 0.9 mag. 

Files needed for each cluster to conduct analysis (* indicates a file that can be made within the analysis run):
1. .phot file
2. New Coor file
3. G magnitudes file*
4. Gaia matches file*
5. DBSCAN parameters file*
6. HB parameters file* 
5. VB21 file

Results files created for each cluster by analysis run:
1. Cluster members file
2. Non-members file
3. Candidate Star files
4. Gaia proper motion plots
5. 6 CMDs

Cumulative files created for all clusters analyzed at that point:
1. Candidate star CMDs
2. Analysis inventory - all the clusters that have been analyzed so far and on what date
3. Log file
